## 4. Интерфейс

### 4.1 Главное: читаемость при демонстрации экрана

Видео в звонке сжимается, смотрят на маленький экран телефона. Поэтому:

- Целевой экран 1920×1080, браузер на весь экран. Всё помещается без горизонтального скролла и без масштабирования браузера.
- Размеры по умолчанию: интерфейс 20px, теория 22px, код в редакторе 24px, консоль 22px, line-height 1.6. Кнопки A− / A+ меняют размер (диапазон 16–40px, шаг 2), значения сохраняются.
- **Режим «Крупно»** (кнопка + горячая клавиша): +6px ко всем размерам, второстепенные элементы скрываются, шапка сворачивается в тонкую полосу.
- Контраст текста не ниже 7:1 в тёмной и светлой темах. Без тонких начертаний (минимум 400, в коде 500). Никаких мелких серых подписей. Крупные кликабельные области.
- Минимум анимаций и плавных градиентов на больших площадях (плохо сжимаются в видео). Курсор в редакторе толстый и заметный. Строка с ошибкой подсвечивается ярко.
- Тёмная тема по умолчанию, светлая переключателем.

### 4.3 Экраны

**Главная (дашборд)**
- Крупная кнопка «Продолжить: Урок N — …» (последняя открытая позиция).
- Карта курса: блоки и карточки уроков (номер, название, статус «не начат / в процессе / пройден», кольцо прогресса по задачам, метки МЦКО-заданий, которые урок закрывает).
- **«Карта МЦКО»:** 13 плиток по типам заданий (раздел 8). Цвет и процент = доля решённых задач с соответствующей меткой `mcko`. Клик → список уроков по этому заданию.
- Общий прогресс.

**Урок (основной экран)**: две колонки с перетаскиваемым разделителем (по умолчанию 42% / 58%, положение запоминается).

*Слева:* шапка урока и вкладки «Теория» | «Задача 1 ✓» | «Задача 2» | … (статусы: не начата / в процессе / решена).
- «Теория» — отрендеренный `lesson.md`. У python-блоков кнопки «▶ В редактор» (подставляет код в песочницу) и «Копировать».
- Задача: условие, примеры ввода/вывода (кнопка «Запустить на примере»), поле ответа (для типов answer/predict), подсказки по одной («Подсказка 1/3»), кнопки «Назад / Дальше».

*Справа сверху:* редактор. Над ним полоса: `main.py`, «▶ Запустить» (Ctrl+Enter), «✔ Проверить» (Ctrl+Shift+Enter, только для задач с тестами), «■ Стоп», «↺ Сбросить к шаблону», A−/A+.

*Справа снизу:* вкладки «Консоль» | «Тесты».
- Консоль: настоящий интерактивный ввод/вывод.
- Тесты: результаты проверки.
- Внизу консоли «Запустить с примером ▾» (выбор примера 1..k): программа получает ввод из примера, а в консоли он выглядит так, будто его напечатали.

*Поведение:*
- На вкладке «Теория» редактор — песочница урока (свой код на урок). У каждой задачи свой код.
- После ошибки строка с ошибкой подсвечивается в редакторе, а под консолью появляется карточка «Что это значит?»: короткое объяснение на русском по типу ошибки (SyntaxError, IndentationError, NameError, TypeError, ValueError, ZeroDivisionError, IndexError, EOFError и др.) с типичной причиной и советом. Traceback при этом показывается, но путь файла упрощён до `main.py`.
- **Пульт преподавателя** (Alt+T): закрыт по умолчанию и пока закрыт не рендерится в DOM. Внутри: `teacher.md` (план урока на минуты), эталонное решение задачи (кнопка с подтверждением «Показать решение»), разбор. Решения не должны появляться на экране случайно, потому что я показываю экран ученице.
- Кнопка «Отметить урок пройденным» вручную.

**Тренажёр Черепахи** (опционально, в самом конце, если останутся силы; см. урок 20): страница, где вводишь программу на языке исполнителя, а она рисуется на клетчатой сетке с координатами.

## 5. Запуск кода и проверка

- **WebSocket `/ws/run`.** Клиент → сервер: `{type:"run", code, files:[...], stdinPreset?:[...]}`, `{type:"stdin", data}`, `{type:"stop"}`. Сервер → клиент: `{type:"stdout"|"stderr", data}`, `{type:"exit", code, timeMs, reason}`.
- **Выполнение:** отдельный процесс `python3 -u -B` во временной директории (cwd), файл называется `main.py`. Файлы данных урока копируются в cwd. Ввод интерактивный. Промпт `input("...")` виден сразу (поэтому `-u`).
- **Консоль (xterm.js):** локальное эхо набираемой строки, Backspace, отправка по Enter. Ввод пользователя, вывод и ошибки разными цветами. Preset-ввод подаётся построчно, когда программа реально запросила ввод, и отображается как набранный.
- **Лимиты** (`resource.setrlimit` в `preexec_fn` + wall-таймауты): CPU 5 с, память 256 МБ, число процессов ограничено, размер создаваемых файлов 10 МБ, вывод ≤ 200 КБ (дальше обрыв с сообщением), простой в ожидании ввода ≤ 15 мин. Бесконечный `while True` должен останавливаться кнопкой «Стоп» и по таймауту с понятным сообщением на русском.
- **`Runner` — интерфейс** (сейчас реализация subprocess + rlimit). В README опиши, как усилить изоляцию при выкладке на сервер (отдельный контейнер-раннер без сети, gVisor/nsjail и т.п.). Сейчас — локальное использование.
- **Проверка:** `POST /api/check {taskId, code}` → каждый тест запускается неинтерактивно (stdin из теста, таймаут 3 с на тест). Ответ: список `{index, status: ok|wrong|error|timeout}`; для видимых тестов дополнительно input/expected/actual, для скрытых только статус. Задача решена, когда прошли все тесты (включая скрытые).
- **Сравнение:** `exact` (после rstrip у каждой строки и в конце), `tokens` (по пробельным токенам), `float` (с допуском). Задаётся в задаче.
- **Тип `answer`:** `POST /api/answer {taskId, values}`. Поддержка нескольких полей (в МЦКО бывают таблицы ответов). Нормализация: пробелы, запятая/точка, регистр букв (для систем счисления). При ошибке только «неверно», без раскрытия ответа. После 3 неверных попыток предложить подсказку.
- **Тип `predict`** («Что выведет программа?»): показывается код (только чтение, кнопка «В редактор»), поле ответа — вывод программы (многострочный). После ответа кнопка «Проверить запуском»: код запускается, реальный вывод показывается рядом.

## 6. Хранение состояния

SQLite в `/data/app.db` (volume). Во всех таблицах колонка `student_id TEXT DEFAULT 'default'` (задел на будущее; входа и аккаунтов сейчас НЕТ).

- **Код:** по каждой задаче и по песочнице каждого урока. Автосохранение (debounce ~600 мс) и при закрытии вкладки; при открытии восстанавливается.
- **Прогресс:** статус задачи (не начата / в процессе / решена), число попыток, дата решения, последний результат тестов. Статус урока: автоматически (все `required` задачи решены) + ручная отметка.
- **Настройки:** размеры шрифтов, тема, режим «Крупно», положение разделителей, автодополнение, последняя открытая позиция (урок/вкладка).
- **Бэкап:** `GET /api/backup` (скачать JSON со всем состоянием), `POST /api/restore`, кнопка в настройках. `make backup` кладёт копию в `./data/backups/`.
- Прогресс привязан к стабильным `id` задач и уроков: если я правлю текст условия, прогресс не теряется. Если правлю тесты уже решённой задачи, статус «решена» сохраняется (но можно «перепроверить»).

## 7. Формат контента

```
content/
  curriculum.yaml
  lessons/
    01-basics-recap/
      lesson.md      # теория, левая колонка
      tasks.yaml     # задачи
      teacher.md     # пульт преподавателя (ученице не показывается)
      data/          # файлы данных для задач (если нужны)
  _gen/              # скрипты детерминированной генерации файлов данных
```

**`curriculum.yaml`:** блоки и уроки в порядке прохождения. Порядок меняется правкой этого файла.

```yaml
blocks:
  - id: basics
    title: Основы Python
lessons:
  - id: 01-basics-recap
    block: basics
    title: "Повторение: print, переменные, input"
    minutes: 50
    mcko: []               # какие типы заданий МЦКО (1–13) урок закрывает
    allowed_imports: []    # какие import впервые разрешены с этого урока (накопительно)
```

**`lesson.md`:** front matter (`title`, `subtitle`, `goal`) + GFM Markdown. Расширения:
- формулы KaTeX: `$N = 2^i$`;
- врезки директивами: `:::tip`, `:::warn`, `:::mcko` (связь с МЦКО), `:::think` (вопрос «подумай»), `:::spoiler[Показать ответ]` (сворачиваемый ответ);
- блоки ` ```python ` получают кнопку «▶ В редактор»; вывод программы оформляй блоком ` ```text `.

**`tasks.yaml`** (список):

```yaml
- id: l06-t3                 # стабильный уникальный id; на него завязан прогресс
  type: code                 # code | answer | predict
  title: Объём сообщения
  level: 2                   # 1 разбираем вместе, 2 по образцу, 3 сама, 4 со звёздочкой
  required: true             # false = дополнительная / звёздочка
  homework: false
  mcko: [9]
  statement: |               # Markdown
    ...
  input_format: ...          # для code
  output_format: ...
  starter: |                 # шаблон кода
  examples:                  # показываются в условии
    - {input: "...", output: "..."}
  tests:                     # для code: ≥5 тестов, первые 2 = примеры, остальные hidden: true
    - {input: "...", output: "...", hidden: true}
  checker: exact             # exact | tokens | float
  files: [data/13.txt]       # копируются в cwd при запуске
  code: |                    # для predict: показываемый код
  answer: ...                # для answer/predict: строка | список полей [{label, value}]
  hints: [..., ..., ...]     # 2–3 подсказки по нарастающей
  solution: |                # эталон на Python: используется verify и пультом преподавателя
  explanation: |             # разбор для преподавателя
```

**`teacher.md`:** цели урока; план на 45–50 минут по блокам (разминка / теория / «предскажи» / задачи / итоги) с реальными минутами, итого 45–50; как объяснять (аналогии, что рисовать и проговаривать); типичные ошибки ученицы; что вырезать, если не успеваем; что дать на дом.

**Файлы данных** (например, `13.txt` для файловых задач) генерируются детерминированно (фиксированный seed) скриптами из `content/_gen/`. Ответы вычисляются эталонным решением.

## 8. МЦКО по информатике (10 класс): что нужно закрыть

**Главный приоритет курса.** Демоверсия МЦКО-2026 — 13 заданий, ответы: числа, слова или небольшие таблицы. PDF положу в `reference/mcko-2026-demo.pdf`; если файла нет, опирайся на таблицу ниже.

| № | Тип задания |
|---|---|
| 1 | Неравномерное двоичное кодирование, условие Фано: часть кодов известна, найти минимальную длину сообщения |
| 2 | «Автомат»: алгоритм над двоичной записью числа (дописывание битов зависит от чётности), найти наименьшее N по условию на результат |
| 3 | Арифметика в разных системах счисления, включая дробные числа; ответ в заданной системе (например, 16-ричной) |
| 4 | Растровое изображение: размер, глубина цвета, доп. биты прозрачности, объём памяти → максимальное число цветов |
| 5 | Логическая функция: по неполной таблице истинности определить, какому столбцу какая переменная соответствует |
| 6 | Слова фиксированной длины из заданного алфавита в алфавитном порядке: номер первого слова с ограничениями (нет буквы X, нет двух соседних Y) |
| 7 | Сети TCP/IP: IP-адрес и маска → номер узла / адрес сети (поразрядная конъюнкция) |
| 8 | Модульная арифметика из RSA: (d·e) mod f(n) = 1, f(n) = (p−1)(q−1), найти d в диапазоне |
| 9 | Информационный объём: серийные номера из N символов, объём всей базы → минимальная мощность алфавита |
| 10 | Исполнитель Черепаха (Вперёд/Назад/Направо/Налево/Поднять хвост/Опустить хвост, Повтори k [...]): число точек с целыми координатами внутри пересечения фигур |
| 11 | Система счисления с основанием > 10 (например, 12), неизвестная цифра x, кратность числа 13, частное в десятичной системе |
| 12 | Дополнительный код отрицательного числа (8 бит) |
| 13 | Файл с последовательностью целых чисел: найти N (минимальное число, не кратное 15), посчитать пары соседних элементов, кратных N, и максимальную сумму таких пар; ответ — таблица из двух чисел |

**Как это использовать**

- Каждый урок в `curriculum.yaml` помечает `mcko`, какие типы закрывает. Каждая задача в стиле МЦКО помечается `mcko: [номер]`. Это питает «Карту МЦКО».
- Задачи в стиле МЦКО пиши **оригинальные**: тот же тип, но другие числа, алфавиты, формулировки. Не копируй текст демоверсии.
- Для каждого типа учим **два способа**: «руками» (формулы, схема рассуждения, бумага) и «программой» (Python как инструмент перебора/вычисления + проверка своего ручного ответа). Ученица должна понимать теорию, а не просто запускать код.
- Задачи `type: answer` — обязательная часть МЦКО-уроков: на МЦКО вводится ответ, а не программа. Решается руками, кодом или тем и другим — как ей удобнее.
- Пробный вариант (урок 21): 13 оригинальных заданий в формате МЦКО, режим с таймером, итоговая страница «что решено / где слабо» (по меткам `mcko`).

## 9. Учебный план: 21 урок

Один урок = одна неделя. До конца 10 класса примерно 25 недель, остаётся запас на повторение. Python-основы перемежаются теорией по информации: школа сейчас проходит единицы информации и растровое кодирование, поэтому уроки 6 и 11 идут параллельно со школой.

**Блок «Основы Python» (1–5)**
1. Повторение: `print`, переменные, `input`, типы (int/float/str), преобразование `int(input())`.
2. Числа: `+ − * / // % **`, порядок действий, цифры числа через `//` и `%`, остатки (фундамент для МЦКО 8, 11, 13).
3. Строки I: конкатенация, умножение строки, `len`, f-строки, сравнение строк, преобразование типов (как в задачах «ввели две строки — вывести большую 5 раз»).
4. Условия: `if/else`, операторы сравнения, отступы, `if/elif/else`.
5. Сложные условия: `and/or/not`, вложенные `if`, приоритет; разбор таблиц «условие → результат» (мост к логике, МЦКО 5).

**Блок «Циклы и информация» (6–11)**
6. Количество информации: бит, байт, Кбайт и далее, N = 2^i, мощность алфавита, объём текста, «серийные номера» (МЦКО 9). Python как калькулятор, `import math`, `math.ceil` (первый разрешённый импорт).
7. Цикл `while`: счётчик, условие, бесконечный цикл и как его остановить, цифры числа в цикле.
8. Цикл `for` и `range`: все формы `range`, трассировочные таблицы.
9. Строки II: индексы, срезы, перебор символов, `in`, `count/find/upper/lower`.
10. Накопители: сумма, количество, max/min, делители, кратность, простое число (МЦКО 13, 8).
11. Растровая графика: пиксель, глубина цвета, палитра, объём изображения, прозрачность (МЦКО 4).

**Блок «Структуры и системы счисления» (12–15)**
12. Списки (создание, индексы, `append`, перебор, `sum/min/max`, срезы) + множества кратко (в школе проходят «Множества в Python»).
13. Функции: `def`, параметры, `return`; функции-помощники (`digit_sum`, `is_prime`, `to_binary`).
14. Системы счисления I: позиционная запись, перевод 10↔2↔8↔16 вручную и кодом (`while` с `//`, `%`), `bin()`/`int(s, base)`, группировка битов (МЦКО 3, 11).
15. Системы счисления II: дробные числа, арифметика в разных системах, основание 12 и неизвестная цифра перебором, дополнительный код 8 бит (МЦКО 3, 11, 12).

**Блок «МЦКО-практикум» (16–21)**
16. Кодирование: равномерные и неравномерные коды, префиксное свойство / условие Фано, однозначное декодирование, минимальная длина сообщения (МЦКО 1).
17. Перебор: вложенные циклы, `itertools.product`, нумерация слов (`enumerate`), ограничения на слова (МЦКО 6); «автомат» (МЦКО 2); RSA-подбор (МЦКО 8).
18. Логика: таблицы истинности, перебор всех наборов, импликация/эквиваленция в Python, сопоставление столбцов (`itertools.permutations`) (МЦКО 5); IP-адреса и маска, побитовое `&` (МЦКО 7).
19. Файлы: `open`/`with`, `read().split()`, список чисел, соседние пары, фильтры по кратности (МЦКО 13).
20. Исполнитель Черепаха (МЦКО 10): трассировка, координаты и направления, пересечение фигур, подсчёт целых точек. Фигуры бери прямоугольные и простые ортогональные. Тренажёр Черепахи, если успеешь.
21. Пробный вариант МЦКО + разбор слабых мест.

Темы каждого урока раскрывай полностью, без пропусков. Задачи подбирай так, чтобы они реально занимали 45–50 минут. Если по лимитам придётся сокращать, режь хвост (тренажёр Черепахи, урок 21), но не качество уроков 1–19.

## 10. Правила написания уроков (самое важное для контента)

Ученице программирование даётся тяжело. Материал должен быть очень последовательным.

**Структура урока**
- «Цель урока»: что она умеет после урока (1–3 пункта) и «Связь с МЦКО».
- Теория короткая: ≤ 500 слов на урок, одна идея на раздел, каждый новый приём сразу с примером. Минимум 3 запускаемых примера, каждый следующий отличается от предыдущего одной деталью.
- «Что выведет?» (`:::think` со `:::spoiler`) перед запуском ключевых примеров: сначала предсказание, потом запуск.
- Для циклов и условий трассировочные таблицы (шаг | переменные | вывод) в Markdown.
- «Типичные ошибки»: 2–3 ошибки с настоящим текстом сообщения Python и объяснением.
- Итоги: 3–5 пунктов.

**Задачи (7–10 на урок)**
- Лесенка `level` 1→4: (1) разбираем вместе, почти копия примера с одним изменением; (2) по образцу; (3) самостоятельно; (4) звёздочка (`required: false`).
- Минимум 1 задача `predict` на урок.
- Формат как в Яндекс.Учебнике: «Входные данные / Выходные данные» + примеры. Формулировки короткими предложениями. Контексты из жизни 10-классницы (магазин, оценки, игры, расписание), без детскости.
- В `input()` в задачах с автопроверкой не пиши текстовых подсказок.

**Словарь и конструкции**
- Не используй в условиях, заготовках и эталонных решениях ничего, что не вводилось в предыдущих уроках (в том числе `import`, см. `allowed_imports`). Нужна новая функция или приём: объясни при первом появлении.
- Единая терминология на протяжении курса (переменная, значение, строка, условие, цикл, итерация…). Каждый термин определяется при первом использовании.
- Имена переменных в примерах осмысленные английские (`name`, `age`, `total`); `i`, `n`, `s` только в привычных ролях.

**Для МЦКО-уроков (6, 11, 14–21)**
- Сначала теория и ручной метод с разобранным примером, затем «проверь программой».
- Каждый тип МЦКО: минимум 4 оригинальные задачи по нарастающей, от прямого применения формулы до полноценного МЦКО-уровня.
- В `teacher.md` — как объяснить теорию устно за 5 минут.

## 11. Качество и проверка

- **`scripts/verify_content.py`** (`make verify`):
  - для каждой задачи `code` прогоняет `solution` по всем `tests` через тот же Runner и сверяет с `output`;
  - для `answer`/`predict` вычисляет ответ эталонным кодом (если задан `solution`) и сверяет с `answer`;
  - проверяет схему: обязательные поля, уникальность `id`, ≥5 тестов, ≥2 hints, наличие `teacher.md`, существование `files`;
  - проверяет, что в `solution` нет импортов вне накопительного `allowed_imports`;
  - проверяет валидность ссылок на уроки в `curriculum.yaml`;
  - выводит объём урока (слова теории, число задач).
  Любая ошибка даёт ненулевой код возврата.
- **Ожидаемые `output` в тестах пиши независимо от `solution`** (вручную или другим способом), чтобы verify был настоящей перекрёстной проверкой. Расхождение = ошибка, которую нужно разобрать, а не «подогнать» одно под другое.
- Тесты покрывают граничные случаи (пустые строки, нули, отрицательные числа, равные значения, максимумы), чтобы решение нельзя было угадать по примеру.
- **`pytest`** для бэкенда: Runner (лимиты, таймаут, интерактивный stdin, обрыв вывода), checker'ы, API check/answer, persistence (код и прогресс переживают перезапуск), backup/restore.
- Если можешь запустить браузерные проверки (Playwright), сними скриншоты 1920×1080 главной, урока (теория + задача) и режима «Крупно» и убедись, что ничего не обрезается, не налезает и читается. Если не можешь, аккуратно проверь вёрстку по коду и честно напиши в README, что визуально не проверялось.
